## 5. Selected API Strategy and Rationale

### Decision: Use `/api/v2.1/search-file/` as Primary Endpoint

**`/api2/search/` is NOT usable** on Seafile CE 12.0.14. Returns 403 even with admin credentials. May be Pro/Enterprise only or require full-text indexing configuration.

### Global Search Workaround

Since `/api/v2.1/search-file/` requires a `repo_id`, global search will be implemented by:

1. Fetch list of all accessible libraries (`GET /api2/repos/`)
2. For each library, call `/api/v2.1/search-file/?q={query}&repo_id={id}`
3. Merge results with library name attached
4. Sort by relevance

**Performance**: With N libraries, this makes N API calls per search. For typical users (1-10 libraries), this is acceptable. The API calls can be parallelized.

### Search Scope Options

| Scope | Implementation | API Calls |
|-------|---------------|-----------|
| Current Library | Single call with current `repo_id` | 1 |
| All Libraries | Parallel calls to all repos | N |
| My Libraries | Filter repos where owner = current user | N (filtered) |

**v0.2.3 default**: Current Library search (single API call).  
**v0.2.3 optional**: Global search across all libraries (parallel calls).

### Why This Works

- `/api/v2.1/search-file/` is **reliable** (verified)
- Case-insensitive matching handles most user intent
- Recursive search finds files in subdirectories
- No pagination needed for most users (files per repo are manageable)
- Library list is already cached in memory (from initial load)

## 8. Server/API Quirks Discovered

| Quirk | Impact | Workaround |
|-------|--------|------------|
| `/api2/search/` returns 403 on CE 12.0.14 | Cannot use global search endpoint | Use `/api/v2.1/search-file/` with per-repo calls |
| `/api/v2.1/search-file/` has no pagination | All results returned at once | Acceptable for typical library sizes |
| `/api/v2.1/search-file/` returns no repo context | Cannot show library name in results | Resolve from cached library list |
| `/api/v2.1/search-file/` returns `type: "folder"` not `"dir"` | Code must check for `"folder"` | Use `type === "folder"` in comparisons |
| `/api/v2.1/search-file/` invalid repo returns HTML 500 | Not a JSON error | Validate repo_id before calling; catch non-JSON responses |
| Empty `q` returns `{"error_msg":"q invalid."}` | Client must enforce minimum query length | Validate q length ≥ 1 before API call |
| Spaces in query may not match underscores | `contrat theses` does not find `contrat_theses` | Users must type exact separators |

## 9. Proposed UI/UX (Revised)

### Search Flow

```
ToolBar
  Search Field (text input)
    debounce (300ms)
    minimum query length (2 chars)
    API call: searchFilesInRepo(query, repo_id)
      Results Panel
        Loading state
        Results list
          Each result:
            Icon (file/folder)
            Name (filename)
            Path (directory)
            Size (files only)
            Library name (from repo cache)
        No results state
        Error state
        Clear button
```

### Search Field Behavior

| State | Behavior |
|-------|----------|
| Empty | Show placeholder "Search in {library_name}..." |
| Typing | Debounce 300ms, then search if >= 1 char |
| Searching | Show loading spinner |
| Results | Show results list below search field |
| No results | Show "No results found" message |
| Error | Show error message with retry option |
| Clear | Click X or press Escape to clear and return to browse |

### Result Interaction

| Result Type | Action |
|-------------|--------|
| **File** | Navigate to containing folder (path minus filename), highlight file |
| **Folder** | Navigate directly to folder path |

### Keyboard Interaction

| Key | Action |
|-----|--------|
| `Escape` | Clear search, return to normal browse |
| `Enter` | Execute search (if debounced search has not triggered yet) |

### Search Scope

v0.2.3 supports two modes:

| Scope | Trigger | API Calls |
|-------|---------|-----------|
| **Current Library** | User is browsing a library, types in search | 1 call |
| **All Libraries** | User clicks "Search All" or is at root | N parallel calls |

**Default**: Current Library when browsing, All Libraries when at root.

## 13. Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| `/api2/search/` unavailable on CE | No global search with rich metadata | Use per-repo search with library list iteration |
| No pagination in `/api/v2.1/search-file/` | Large result sets returned at once | Acceptable for typical library sizes; monitor in production |
| Missing repo context in response | Cannot show library name in results | Resolve from cached library list (already in memory) |
| Invalid repo_id returns HTML 500 | Non-JSON error breaks parsing | Validate repo_id before calling; catch non-JSON responses |
| Spaces vs underscores in queries | User types "contrat theses" but file is "contrat_theses" | Document behavior; no client-side fix needed |
| Token expiration during search | 401 errors during search | Reuse existing auth handling |
